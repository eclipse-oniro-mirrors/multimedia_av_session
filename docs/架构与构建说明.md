# 播控框架架构与构建说明

## 分层模型

```text
应用 / JavaScript / C / CJ / Taihe
                 |
              框架绑定（NAPI / CJ / Taihe / OHAVSession）
                 |
              原生客户端代理（AVSessionManagerImpl / AVSessionProxy / AVControllerProxy / AVCastControllerProxy）
                 |
           IPC / 序列化边界（Proxy ↔ Stub）
                 |
        AVSessionService 系统服务（SAID=3010）
           |                |                |
       基础播控          音视频投播        分布式播控
    会话/控制器/焦点   AVRouter/Cast+    Source/Sink/软总线/迁移
    /后台音频/多用户   /PCM/HiPlay       /MigrateWithNext/SuperLauncher
           \                |                /
            外部依赖适配（音频、应用管理、权限、按键、协同、分布式对象、插件库）
                 |
        HDI / Cast+ 引擎 / 软总线 / 分布式数据对象 / 协同服务
```

## 模块职责

- `interfaces/` 定义公共契约（C 接口、C++ 内部 API）和数据类型（会话描述符、控制命令、播放状态、元数据、队列、投播命令、设备信息）。
- `frameworks/` 将公共 API 转换为原生客户端代理操作，并提供 NAPI、CJ、Taihe 和 OHAVSession 多语言绑定。
- `services/session/server` 是 AVSession 系统服务（SAID=3010）核心实现，承载三大模块：基础播控（会话项、控制器项、会话栈、焦点策略、后台音频、多用户）、音视频投播（AVRouter、HwCastProvider、AVCastControllerItem、PcmCastSession）、分布式播控（remote/Source-Sink-Syncer、softbus、migrate）。
- `services/session/ipc` 维护服务、会话、控制器和投播控制器的 IPC 接口、IDL 回调、代理和 Stub。
- `services/session/adapter` 连接音频、应用管理、权限、按键、协同、分布式对象和插件库等外部依赖。
- Cast+ 引擎、软总线、分布式数据对象、协同服务库、设备管理负责连接具体设备与跨设备能力。

## 三大模块边界

| 模块 | 入口类 | 通信方式 | 跨模块交互 |
| --- | --- | --- | --- |
| 基础播控 | `AVSessionService`、`AVSessionItem`、`AVControllerItem` | 本地 IPC | 为投播/分布式提供会话和 TopSession；`MirrorToStreamCast` 镜像到投播 |
| 音视频投播 | `AVRouter`、`AVCastControllerItem`、`HwCastProvider` | IPC + Cast+ 引擎 | 通过 `CreateSessionByCast` 接入服务；HiPlay/URLCasting 经 adapter 协同 |
| 分布式播控 | `RemoteSessionSource/Sink`、`SoftbusSession`、`MigrateAVSessionServer/Proxy` | 分布式数据对象 + 软总线 | `avsession_service_ext.cpp` 集成迁移入口；`AudioDeviceManager` 配合迁移切换输出 |

## 构建入口

- `bundle.json` 声明组件、系统能力（SystemCapability）、依赖、功能开关、框架目标和服务目标。
- `config.gni` 定义软总线分布式播控、分布式数据对象、后台音频控制、Trace、SysEvent、HiCollie、设备管理、多用户多音区、命令限流等可选能力。
- `av_session_ohos_sources.gni` 汇总源文件参与构建。
- `frameworks/js/napi/session:avsession_napi` 构建 JavaScript 绑定。
- `interfaces/kits/c:avsession_capi` 构建 C 接口。
- `services/session:avsession_service_packages` 构建播控系统服务。
- `sa_profile:av_session_sa_profile` 打包系统能力配置。

## 系统能力和 IPC

`AVSessionService` 是系统能力（SAID=3010），`run-on-create` 为 true，`distributed` 为 true，`dump_level` 为 1。客户端代理通过系统能力管理器获取服务远程对象。

IPC 采用标准 OpenHarmony Proxy/Stub 模式：

- 服务接口码定义在 `services/session/ipc/base/iavsession_service_ipc_interface_code.h`，`AvsessionSeviceInterfaceCode` 枚举属于兼容性契约。
- Stub 端 `OnRemoteRequest` 校验 `IsLocalCalling()`，除 `SERVICE_CMD_SEND_COMMAND_TO_REMOTE` 外禁止跨设备 RPC。
- 每个 Handle 方法经 `PermissionChecker::CheckPermission` 校验后分发到服务实现。
- 会话、控制器和投播控制器分别维护 IDL、代理和 Stub；序列化顺序及接口码属于兼容性契约。
- 回调 IDL 中控制器元数据回调 `OnMetaDataChange` 标注 `[ipcincapacity 1024]`；投播控制器回调 `OnMediaItemChange` 同样为 1024；投播控制器代理默认 IPC 容量提升至 1MB。

## 功能开关

`config.gni` 定义以下可选功能开关，依赖功能开关的行为必须明确写出开关名称：

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| `av_session_enable_dsoftbus` | true | 软总线分布式播控（softbus/migrate） |
| `multimedia_av_session_enable_data_object` | false（有 data_object 部件时 true） | 分布式数据对象同步（remote） |
| `multimedia_av_session_enable_background_audio_control` | false | 后台音频静音控制 |
| `multimedia_av_session_enable_trace_control` | true | Hitrace 控制 |
| `multimedia_av_session_enable_sysevent_control` | true | HISyseEvent 控制 |
| `multimedia_av_session_enable_hicollie` | true（无 hicollie 部件时 false） | HiCollie 看门狗 |
| `multimedia_av_session_enable_device_manager` | false（有 device_manager 部件时 true） | 设备管理（迁移触发） |
| `av_session_enable_multi_user_audio_zone_feature` | false（有 car_feature 部件时 true） | 车机多音区 |
| `av_session_enable_start_stop_on_demand` | false | 按需启停 |
| `av_session_enable_input_redistribute` | false | 输入重分发 |
| `av_session_enable_raise_command_rate_limit` | false | 命令限流 |

功能开关规则：

- 关闭功能开关后，不能破坏基础会话、控制器、投播和分布式路径。
- 功能开关内的符号、依赖和行为不能无保护地泄漏到基础构建。
- 涉及分布式数据对象、软总线、设备管理或车机音区的功能，必须允许对应依赖不存在。
- 新增开关需要说明默认值、所属模块、依赖、降级行为和测试覆盖。

## 参考来源和修改边界

| 内容 | 优先检查的参考来源 | 边界 |
| --- | --- | --- |
| 公共 API、类型和错误码 | `interfaces/` | 变更后同步原生客户端、多语言绑定、版本脚本和测试 |
| IPC 协议 | `services/session/ipc/base/`、`proxy/`、`stub/`、`idl/` | 两端同步修改，保持接口码和序列化顺序 |
| 构建目标和依赖 | 对应目录的 `BUILD.gn`、`bundle.json` | 不直接修改生成产物，不绕过条件依赖 |
| 功能开关 | `config.gni` 及相关 `.gni` | 明确默认值、依赖、关闭行为和降级路径 |
| 系统能力注册 | `sa_profile/`、服务入口 | 同时检查权限、生命周期和服务恢复 |
| 诊断事件 | `hisysevent.yaml`、对应 DFX 代码 | 不输出 PCM、令牌值、设备地址和未脱敏身份 |
| 版本符号 | `*.versionscript` | 不破坏已导出符号和 ABI 兼容性 |

当公共契约、实现行为和知识文档不一致时，以当前源码和构建配置为证据；不要把单一实现路径推断为稳定公共 API 契约。

## 修改检查清单

1. 确认任务所属模块（基础播控/音视频投播/分布式播控）和跨模块边界。
2. 找到公共契约（`interfaces/`）和内部接口（`ipc/base/`）。
3. 跟踪客户端代理（`frameworks/`）、服务端 Stub（`ipc/stub/`）和服务实现（`server/`）。
4. 检查会话/控制器生命周期、焦点状态转换、投播 castHandle 和分布式同步一致性。
5. 检查功能开关、ABI、版本脚本和依赖影响。
6. 补充正常路径、异常路径、服务不可用和跨设备断连路径测试。

## 验证命令

构建命令从完整 OpenHarmony 源码根目录执行，不在 `multimedia_av_session` 子目录执行：

```sh
# 构建完整系统
./build.sh --product-name rk3568 --ccache --build-target make_all

# 只构建播控框架组件
./build.sh --product-name rk3568 --ccache --build-target av_session
```

验证步骤：

1. 读取变更目标所在目录的 `BUILD.gn`，确认目标名、依赖和测试目标。
2. 根据变更范围选择完整系统构建或 `av_session` 组件构建。
3. 执行对应单元测试、服务级测试或 `services/session/server/test/fuzztest/` 目标。
4. 执行 `git diff --check`，并复查接口、配置、日志和文档索引。
5. 若产品名、源码根目录或构建环境不同，记录实际使用的命令，不能将示例命令伪装成已执行结果。

## 完成标准

变更只有在源码、配置、接口兼容性、测试和文档影响均已检查，并且验证结果已记录时才算完成。无法执行构建或设备测试时，必须记录具体原因、已完成的替代检查和剩余风险。
