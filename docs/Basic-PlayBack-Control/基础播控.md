# 基础播控模块

## 模块概述

基础播控模块实现本地音视频会话的创建、管理、控制和状态同步能力。它是播控框架的核心，为应用提供会话接口，为系统播控中心提供控制器接口，并管理焦点策略、后台音频控制、多用户隔离等系统级行为。

## 范围

基础播控覆盖以下能力，跨模块边界（投播、分布式）的交互在对应主题文档中说明：

- 会话创建、激活、停用、销毁的全生命周期管理，含会话描述符、元数据、播放状态、队列、扩展和会话事件。
- 控制器创建与绑定，控制命令、按键事件、通用命令转发，元数据与播放状态过滤掩码同步。
- 会话栈容器管理（增删查、排序、上限 `SESSION_NUM_MAX=50`、内存回收）。
- 焦点策略：音频渲染状态监听、TopSession 选择、延迟停止（5s）、会话栈排序。
- 后台音频控制：无 AVSession 的三方后台应用音频静音、前台恢复、HasAVSession 校验。
- 多用户隔离：按 userId 隔离会话栈与 TopSession、账户切换、车机多音区。
- 音频设备管理：首选输出设备监听、设备插拔、迁移输出切换配合。
- IPC 通信：服务/会话/控制器 Proxy-Stub、接口码、回调 IDL、本地调用约束。
- 多语言绑定：NAPI、C 接口、CJ、Taihe、OHAVSession。
- 调试转储：AVSessionDumper 元数据/会话/控制器/错误/信任设备信息。

不在此模块：投播路由与 Cast+ 引擎对接（见[音视频投播.md](../AV-BroadCast/音视频投播.md)）、分布式数据对象同步与软总线迁移（见[分布式播控.md](../Migrate-PlayBack-Control/分布式播控.md)）。

```cpp

class FocusSessionStrategy {

    void RegisterFocusSessionChangeCallback(const FocusSessionChangeCallback&);  // :43
    void RegisterFocusSessionSelector(const FocusSessionSelector&);              // :44
    void HandleAudioRenderStateChangeEvent(const AudioRendererChangeInfos&);    // impl:137
    void UpdateFocusSession(const std::pair<int32_t,int32_t>& key);            // impl:198
    void DelayStopFocusSession(const std::pair<int32_t,int32_t>& key);          // impl:228 — 延迟5000ms

```

**焦点选择流程**：
1. 音频渲染状态变化 → `HandleAudioRenderStateChangeEvent` 更新 `currentStates_[<uid,pid>]`
2. 新进入播放（lastState 非 running → running）→ `UpdateFocusSession`：构造 FocusSessionChangeInfo → 调 selector_ 选择会话 → 调 callback_ 通知 service
3. 从播放转停止（running → stop）→ `DelayStopFocusSession`：延迟 5s 后 callback_ 通知停止（期间恢复则取消）
4. `AVSessionService::HandleFocusSession`（impl:851）接收回调，按 uid 查找 sessionItem 更新 topSession

允许的流类型（`ALLOWED_MEDIA_STREAM_USAGE`）：MUSIC / MOVIE / AUDIOBOOK / VOICE_COMMUNICATION 等。

## 约束

- 会话必须遵循创建、激活、运行、停用、销毁的状态机；销毁后控制器不可用，回调不可重新唤醒已停止或释放的会话。
- 同一 pid 同一 ability 仅允许一个会话，重复创建返回 `ERR_SESSION_IS_EXIST`；会话总数上限 `SESSION_NUM_MAX=50`，超限返回 `ERR_SESSION_EXCEED_MAX`。
- 会话栈空时延迟 240s 写 `/proc/<pid>/reclaim` 触发内核内存回收，修改容器逻辑不得破坏上限和回收。
- 焦点决策对同一组活动会话应保持确定性；新进入播放触发 `UpdateFocusSession`，停止延迟 5s 后通知（期间恢复则取消）。
- TopSession 变化需通知所有 SessionListener 并通过 `MirrorToStreamCast` 镜像到投播场景。
- 后台音频静音仅针对无 AVSession 的三方后台应用，前台恢复时解除静音；`HasAVSession` 校验避免误静音。
- 多用户隔离：每用户独立会话栈与 TopSession，目录 `/data/service/el2/<userId>/av_session/`；账户 SWITCHED/REMOVED 时清理。
- 控制命令分发需校验会话状态、命令有效性、调用方身份；元数据/播放状态按掩码增量同步，`CopyToByMask`/`GetChangedStateMask` 保证仅传递变更字段。
- IPC 只有 `SERVICE_CMD_SEND_COMMAND_TO_REMOTE` 允许跨设备 RPC，其余仅本地调用；接口码与序列化顺序属兼容性契约。
- 控制器回调 `OnMetaDataChange` IPC 容量 `ipcincapacity 1024`，序列化不得突破边界。

## 安全与隐私

- Stub 层每个 Handle 方法经 `PermissionChecker::CheckPermission` 校验，失败返回 `AVSESSION_ERROR` 并上报 `CONTROL_PERMISSION_DENIED`。
- 会话创建校验 tag/type/elementName、纠正三方调用者 element、同 pid 唯一会话。
- 元数据（标题、艺术家、专辑、媒体图像、歌词）、包名/Ability、通话元数据（电话号码）属于应用隐私，回调载荷只应包含接口契约要求的信息。
- 不得向一个应用泄露无关应用的包名、会话和状态等非必要信息。
- 设备信息（deviceId、networkId、ipAddress）属于设备隐私，本地输出设备变更回调不暴露给无关应用。
- 禁止日志包含 PCM 内容、媒体元数据原始令牌、设备地址和未脱敏应用数据。
- 无法确认权限、输入合法性或服务可用性时失败关闭，返回稳定错误码并保持已有会话和控制器状态不变。
