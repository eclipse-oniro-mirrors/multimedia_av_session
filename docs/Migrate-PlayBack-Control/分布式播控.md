# 分布式播控模块

## 模块概述

分布式播控模块实现组网内设备之间的会话同步和控制能力。采用 **Source/Sink 双端模型** + **会话同步器(Syncer)** + **软总线(SoftBus)通信** 的架构，并辅以**会话迁移(Migrate)**机制，支持 MigrateWithNext（手机↔手表）和 SuperLauncher（超级终端流转）两种迁移场景。

## 范围

分布式播控覆盖以下能力，三大子系统分别由 `data_object`、`dsoftbus` 功能开关保护：

- 分布式数据对象同步（remote 目录，`multimedia_av_session_enable_data_object`）：
  - Source 端投射会话到远端、同步本地会话信息（元数据/播放状态/队列/事件/扩展）、处理远端回传控制/通用命令、取消投射。
  - Sink 端接收远端会话、同步 6 类远端数据、反向发送控制/通用命令。
  - 会话同步器基于 `DistributedObjectStore("av_session")` 实现两端状态一致，键名常量、SHA256 objectName、500KB 上限。
  - 能力集管理：本地能力收集、远端能力记录、掩码查询过滤。
  - JSON 工具：能力集、会话基本信息、会话描述符序列化。
  - 远程命令处理：跨设备 RPC（`SERVICE_CMD_SEND_COMMAND_TO_REMOTE`）。
- 软总线通信（softbus 目录，`av_session_enable_dsoftbus`）：
  - 会话建立（Socket/Bind/Listen）、QoS（最小带宽 64k、建链时延 0.5-19s）、失败重试 5 次/500ms。
  - 数据传输（定向/广播/Next 专用/消息方式）、车机 A2DP 在线时不发送。
  - 代理/服务端模式（characteristic 路由）、动态加载软总线 C 接口。
- 会话迁移（migrate 目录，`av_session_enable_dsoftbus`）：
  - CROSS 模式（SuperLauncher）：多会话同步、控制器列表/历史、心跳 180s、Base64 兼容安卓 MediaSession。
  - NEXT 模式（MigrateWithNext）：前台会话元数据/播放状态/媒体图片/bundle 图标/有效命令同步、长暂停检测（5 分钟）、音量/设备/协议版本同步、心跳 30s/3600s + 连接检查 5s。
  - 迁移管理单例、引用计数控制软总线 server 生命周期、本地 stub/远端 proxy 创建释放。
- 适配层：DistributedObjectAdapter（ObjectStore/Watcher/StatusNotifier）。
- 服务集成入口：`avsession_service_ext.cpp`（SuperLauncher/MigrateWithNext/设备状态回调）。

不在此模块：本地会话与焦点（见[基础播控.md](../Basic-PlayBack-Control/基础播控.md)）、投屏投音的 Cast+ 引擎路由（见[音视频投播.md](../AV-BroadCast/音视频投播.md)）。分布式数据对象同步（remote）和软总线通信（softbus）是两个不同通道，前者用于 Source/Sink 状态同步，后者用于迁移数据传输。

### 三大子系统

| 子系统 | 目录 | 编译宏 | 通信方式 | 场景 |
|--------|------|--------|----------|------|
| 分布式数据对象同步 | `server/remote/` | `DATA_OBJECT_ENABLE` | 分布式数据对象 | Source/Sink 会话同步 |
| 软总线通信 | `server/softbus/` | `DSOFTBUS_ENABLE` | 软总线 Socket | 会话迁移数据传输 |
| 会话迁移 | `server/migrate/` | `DSOFTBUS_ENABLE` | 软总线 + JSON/二进制协议 | MigrateWithNext / SuperLauncher |

```cpp
// services/session/server/remote/remote_session_syncer_impl.h:37
```

**同步机制**：
1. **对象创建** `Init`（impl:71）：
   - `objectStore_ = DistributedObjectStore::GetInstance("av_session")`
   - `objectName_` = SHA256(`sourceSessionId_ + sourceDevice_ + sinkDevice_`) 转十六进制大写
   - `object_ = objectStore_->CreateObject(objectName_)`
   - 两端用相同输入算出相同 objectName，连接到同一分布式对象
2. **数据写入/读取**：
   - `PutData(key, data)`（impl:102）：`object_->PutComplex(key, data)` — 字节向量写入
   - 序列化：对象 `Marshalling(Parcel)` → 取 `GetData()` 指针 → copy 到 `vector<uint8_t>`
   - 反序列化：`Parcel::ParseFrom` → `Unmarshalling`
   - 大小校验：≤500KB
3. **变更通知**：
   - `OnChanged(sessionId, keys)`（impl:33）：ObjectWatcher 回调，查 `categoryMap` 得 SessionDataCategory，调 `objectDataNotifier_`
   - `OnChanged(name, networkId, onlineStatus)`（impl:54）：设备在线状态变化，`offline` 时调 `objectDisconnectNotifier_`
4. **生命周期** `Destroy`（impl:500）：`UnWatch` + `DeleteObject` + 清空回调

## 会话同步器机制

`RemoteSessionSyncerImpl` 基于 `DistributedObjectStore`("av_session" store) 实现两端状态一致性：

```
Source 写 PutAVMetaData
  → object_->PutComplex("metaData", bytes)
    → 分布式数据对象自动跨设备同步
      → Sink 端 OnChanged(keys) 回调
        → objectDataNotifier_(SESSION_DATA_META, sinkDevice)
          → Sink HandleSessionDataCategory → GetAVMetaData → SetAVMetaData

Sink 写 PutControlCommand
  → object_->PutComplex("controlCommand", bytes)
    → 分布式数据对象自动同步
      → Source 端 OnChanged 回调
        → objectDataNotifier_(SESSION_DATA_CONTROL_COMMAND, sinkDevice)
          → Source HandleSourceSessionDataCategory → ExecuteControllerCommand
```

- 两端用相同输入（`sourceSessionId + sourceDevice + sinkDevice`）经 SHA256 算出相同 objectName，连接到同一分布式对象
- 序列化方式：`Marshalling(Parcel)` → 字节流 → `PutComplex`
- 反序列化：`ParseFrom` → `Unmarshalling`
- 大小校验：`RECEIVE_DATA_SIZE_MAX = 500KB`

## 约束

- 分布式数据对象同步（remote）和软总线通信（softbus）是两个不同通道，不可混淆：前者用于 Source/Sink 会话状态同步，后者用于会话迁移数据传输。
- 功能开关保护：`multimedia_av_session_enable_data_object` 控制分布式数据对象同步，`av_session_enable_dsoftbus` 控制软总线和迁移；关闭后不能破坏基础会话路径，依赖缺失时降级。
- Source/Sink 配对：两端用相同输入（`sourceSessionId + sourceDevice + sinkDevice`）经 SHA256 算出相同 objectName 连接同一分布式对象；objectName 不匹配会导致同步失败。
- 单条数据上限 `RECEIVE_DATA_SIZE_MAX = 500KB`，超限拒绝；序列化用 `Marshalling(Parcel)` → 字节流 → `PutComplex`，反序列化用 `ParseFrom` → `Unmarshalling`。
- 能力集掩码过滤：Source 端用 `GetSinkMetaMaskType`/`GetSinkPlaybackStateMaskType` 基于远端能力集生成掩码，`CopyToByMask` 仅同步远端支持字段。
- 软总线 SocketInfo.name = "Media_Session_RemoteCtrl"，QoS 最小带宽 64k、最大建链时延 19s、最小建链时延 0.5s；建链失败重试 5 次间隔 500ms。
- 一个 networkId 可有多个 proxy（不同 characteristic）共享一个 socket；车机 A2DP 在线时 `SendBytes` 不发送。
- 迁移模式常量属协议契约：`MSG_HEAD_MODE=100`（CROSS/SuperLauncher）、`MSG_HEAD_MODE_FOR_NEXT=101`（NEXT/MigrateWithNext），`data[0]` 区分模式，`data[1]` 为命令类型，`data[2:]` 为负载。
- 迁移心跳：CROSS 180s，NEXT 30s/3600s + 连接检查 5s；长暂停检测 5 分钟通知手表。
- 引用计数 `refs_` 控制软总线 server 生命周期：refs==0 时 `InitSessionServer("AVSession")`，归 0 时 `DestroySessionServer`。
- 跨设备 RPC 仅限 `SERVICE_CMD_SEND_COMMAND_TO_REMOTE`（`RemoteSessionCommandProcess`），其余接口仅本地。
- 迁移 JSON 协议（能力集、会话基本信息、会话描述符、控制命令）和 Base64 二进制兼容（安卓 MediaSession）属跨版本协议，修改需评估兼容性。

## 安全与隐私

- 远端设备授权和网络标识（networkId、deviceId）属设备隐私，能力集交换和会话同步需校验对端身份，无法确认时失败关闭。
- Source 端仅同步远端支持的字段（掩码过滤），不泄露远端不支持或不必要的元数据；回调载荷只应包含接口契约要求的信息。
- 媒体图片同步经 JPEG 压缩 + Base64（NEXT `DoMediaImageSyncToRemote`、Super `ConvertMetadataToJson`），避免传输原始像素图。
- 控制命令反向同步（Sink → Source）需校验命令有效性和会话状态，过期回调不可重新唤醒已停止会话。
- 分布式断连时 `OnChanged(offline)` 触发 `objectDisconnectNotifier_`，上报 `REMOTE_CONTROL_FAILED` 并清理 Syncer、软总线 Socket 和迁移 Proxy/Server。
- RemoteSessionSourceProxy 经 dlopen 动态加载并带 `__attribute__((no_sanitize("cfi")))` 防 CFI，调用加 `AVSESSION_TRACE_SYNC_START` 追踪。
- 禁止日志包含 PCM 内容、媒体元数据原始令牌、远端网络标识、设备地址和未脱敏应用数据。
- 迁移涉及真实设备和组网，修改前必须说明影响范围并等待确认，不得执行未经确认的破坏性命令。
