## 诊断事件（hisysevent）

`hisysevent.yaml` 定义 `AV_SESSION` 域事件：

| 事件 | 类型 | 级别 | 说明 |
| --- | --- | --- | --- |
| `SESSION_SERVICE_START` | BEHAVIOR | MINOR | 服务启动 |
| `FOCUS_CHANGE` | BEHAVIOR | MINOR | 焦点变化（新旧会话、PID/UID、音频信息） |
| `CONTROL_PERMISSION_DENIED` | SECURITY | CRITICAL | 权限校验失败（调用方 UID/PID、会话 ID、按键码、命令） |
| `CONTROL_COMMAND_FAILED` | FAULT | MINOR | 控制命令无响应/超时/无效 |
| `CONTROL_COMMAND_FAILED_RATE` | STATISTIC | MINOR | 命令失败率 |
| `CONTROL_COMMAND_STATISTICS` | STATISTIC | MINOR | 命令统计（各类命令计数） |
| `SESSION_LIFECYCLE_STATISTICS` | STATISTIC | MINOR | 会话生命周期统计 |
| `SESSION_CAST` | BEHAVIOR | MINOR | 投播行为 |
| `SESSION_CAST_CONTROL` | BEHAVIOR | MINOR | 投播控制 |
| `REMOTE_CONTROL_FAILED` | FAULT | MINOR | 远程控制失败（分布式断连） |
| `AVSESSION_WRONG_STATE` | FAULT | MINOR | 错误播放状态 |
| `SESSION_INPUT_REDISTRIBUTE`/`SESSION_INPUT_REDISTRIBUTE_SUCC` | BEHAVIOR | MINOR | 输入重分发 |
| `SESSION_API_BEHAVIOR` | BEHAVIOR | MINOR | API 行为 |
| `PLAYING_COMBIND_AVSESSION_STATIS`/`PLAYING_AVSESSION_STATS` | STATISTIC | MINOR | 播放会话统计 |

诊断事件不输出 PCM、令牌值、设备地址和未脱敏身份。

## Trace 与性能

- `multimedia_av_session_enable_trace_control`（默认 true）控制 Hitrace 打点。
- `AVSESSION_TRACE_SYNC_START` 宏用于分布式同步路径追踪（如 `RemoteSessionSourceProxy`）。
- 焦点变化、会话生命周期、投播路由和迁移流程应保留关键 Trace 点。

## Dump

`AVSessionDumper`（`services/session/server/avsession_dumper.h`）通过 `Dump` 方法响应 `hidumper`，支持参数：

| 参数 | 输出 |
| --- | --- |
| `-show_metadata` | 元数据 |
| `-show_session_info` | 会话信息 |
| `-show_controller_info` | 控制器信息 |
| `-show_error_info` | 错误信息 |
| `-show_trusted_devices_info` | 信任设备信息 |

`SetErrorInfo` 用于在故障路径写入错误信息供 Dump 输出。

## 看门狗与恢复

- `multimedia_av_session_enable_hicollie`（默认 true，无 hicollie 部件时 false）控制 HiCollie 看门狗，`session_xcollie` 负责线程看护。
- 服务死亡恢复：客户端通过 `RegisterServiceDeathCallback` 监听；服务端 `OnCastServerDied` 清理 Cast+ Provider 会话。
- 分布式断连恢复：分布式数据对象 `OnChanged(offline)` 触发 `objectDisconnectNotifier_`，上报 `REMOTE_CONTROL_FAILED` 并清理 Syncer。
- 软总线建链失败重试 5 次，间隔 500ms。
- 迁移心跳：CROSS 模式 180s，NEXT 模式 30s/3600s + 连接检查 5s。
- 会话栈空时延迟 240s 写 `/proc/<pid>/reclaim` 触发内核内存回收。

## 验证命令

构建命令从完整 OpenHarmony 源码根目录执行：

```sh
# 构建完整系统
./build.sh --product-name rk3568 --ccache --build-target make_all

# 只构建播控框架组件
./build.sh --product-name rk3568 --ccache --build-target av_session
```

测试执行步骤：

1. 读取 `services/session/server/test/BUILD.gn` 确认测试目标名。
2. 按变更范围选择对应单元测试目标（如 `avsession_service_test`、`avrouter_test`、`remote_session_source_test`）。
3. 跨边界修改补充模糊测试目标（如 `avsessionservice_fuzzer`、`permissionchecker_fuzzer`）。
4. 执行 `git diff --check` 复查格式、接口和日志。
5. 无法执行时记录原因、替代检查和残余风险。
